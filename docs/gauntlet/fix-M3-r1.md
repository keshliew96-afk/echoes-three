## Decisions (PLAN silent — best-in-class choice recorded)
- D1 Stress stand-in: CDP CPU throttle (x2 / x3) reproduces the critic's contended box deterministically; it slows the whole game (x3 -> 11-27 fps), so per-frame engine work there scales with ticks per frame. Used as an indicator; the gate figure is the critic's GPU-harness scenario.
- D2 Samples are baked at RUNTIME from the recipes (BUILD_BRIEF A9 "WebAudio synthesis only, no audio files" still holds: no asset files ship; the recipe is the asset).
- D3 Rendering happens in a Web Worker with a DSP twin of the kit primitives, not in an OfflineAudioContext: OAC graph construction is main-thread work (~0.1-0.5 ms per recipe in game, 1-3 ms for the first builds of each fresh context). Fidelity measured against Web Audio (tools/gntfixM31-fidelity.mjs): deterministic recipes RMS within 0.75 dB (median 0.00), peaks within 1.36 dB (sub-sample start alignment of multi-tone cues), noise recipes statistically equal. A recipe the record kit cannot replay (reads anything but params.pitch / params.kit or builds nodes itself) stays live — registerCue documents `bake: false`.
- D4 Baked cues play in an AudioWorklet sampler; spatial voices take the PannerNode maths (equal-power azimuth + inverse distance, spatial.gains() = spatial.predict) at their start, so a voice (<= 3.2 s) does not re-pan while the camera moves under it. testTone and live-synthesised voices still use PannerNodes (G3.6 measures those).
- D5 Frame budget: gameplay cue requests queue in the sim listener and start in update(); priority >= 4 (telegraphs, boss) and the first 4 starts of a frame ignore the budget; a request that cannot start within max(100 ms, 2.5 frames) is virtualised and reported (`dropped: 'budget'`, still a `sound` event, counted in voices().dropped.budget and cost().budget.budgetDrops).
- D6 Honest accounting: cost() files every engine main-thread interval per frame — update(), sim-listener handlers, API / nav triggers, meter-worklet messages, bake filing — so the figure can only be conservative (timer 100 us: per-event handler timings add quantisation noise upwards).
- D7 Music: combat / boss notes and all percussion are baked (150-200 notes per 4-bar cycle from 32-48 keys, ~2.5-3 MB per state); calm states' melodic notes (5-56 per cycle, long tails) and pads / drones stay live. A layer sampler per music player keeps intensity layers and crossfades as Web Audio automation.
- D8 Spectral centroid (G3.5 probe metric) is computed in the meter worklet on every 2048-sample block with the AnalyserNode's analysis (Blackman window, |X/N|^2, bins > -140 dB) — no main-thread FFT, full coverage (before: a sampled AnalyserNode FFT a few times per second on the main thread, 1-2 ms/s under probes).
- D9 Listener re-seat dead-band 5 cm (< 0.5 deg azimuth for a source 6 u away).
- D10 Sample memory cap 24 MB (Float32 mono; LRU per variant). Measured: every registered cue (fight list with 2 variants for noise recipes, the rest 1 variant, Audio-tab test phrases on second play) 11.2 MB + the current theme's combat / boss notes 7.1 MB = 18.3 MB (214 keys, 258 variants, 99.7 s of audio rendered by the worker, 7.4 ms of main-thread recording in total).
