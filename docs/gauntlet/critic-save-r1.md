## 1. BLIND BENCHMARK CHECKLIST (written before inspecting any Echoes capture)

Scored later as MET / PARTIAL / NOT MET with evidence. Sources: shipped behaviour of the named games/engines.

### Hades
- B1 Autosave at every safe transition (chamber entry / reward pick / hub return), never mid-fight; a crash or quit resumes at the start of the current chamber with identical build, HP, currencies.
- B2 "Continue" is the focused default on the main menu and resumes the most recent state without asking which file.
- B3 A bad or half-written profile never boots into a crash; the game falls back (backup profile) with a message.
- B4 After a load, every HUD/UI element (boon tray, HP, currencies, cooldowns) already reflects the loaded state on the first playable frame; no stale UI.
- B5 Persistent meta progression and run records survive run ends AND app restarts and are shown on a records/stats screen.

### Slay the Spire
- B6 Resume is deterministic: RNG streams and their counters are saved, so a resumed run produces the same draws/rewards as an un-quit continuation.
- B7 Mid-combat save/resume returns you to the same combat state (enemies, HP, statuses, hand) — nothing re-rolled.
- B8 Continue/abandon: abandoning or overwriting a run in progress requires a confirmation.
- B9 Saves carry a version; mismatched versions are handled (migrated or refused) without a crash.
- B10 Run history persists per run (score, floor/rooms, kills, time, seed) and the end card shows the score with a breakdown/"best" marker.

### Stardew Valley
- B11 Slot list shows per-slot metadata (name, progress/location, money, day/playtime, date) that matches the loaded state exactly.
- B12 Delete is a small secondary control that opens an "Are you sure?" dialog whose default/focused button is the safe one.
- B13 Save writes go to a temp file, then replace the main file, keeping the previous one as `_old`; a torn write leaves the old save loadable.
- B14 Saving is confined to safe points with a visible "Saving…" indicator; the player is told when saving is not possible.
- B15 Load restores position, inventory with counts, world variables (day/season/weather/flags) and the world's daily RNG.

### The Elder Scrolls (Skyrim / Oblivion)
- B16 Manual named slots + quicksave F5 / quickload F9 with an on-screen toast; autosaves rotate among ≥ 2 slots so one bad autosave never costs everything.
- B17 Overwrite asks "Overwrite this save?" and Delete asks "Delete this save?"; both default to the non-destructive choice; Esc cancels.
- B18 Every entry shows character/level, location, playtime, wall-clock date and a screenshot thumbnail, newest first.
- B19 A save from a newer game version or with missing content warns/refuses with a message, never a crash; the file is not modified.
- B20 Load restores exact position/heading, inventory, world flags, active effects with their remaining timers, and the in-flight state of the world (projectiles, AI targets).
- B21 When saving is disallowed (dead, menus, mid-transition, online guest) a clear reason is shown instead of silently doing nothing.

### Save engineering practice (Factorio / Minecraft)
- B22 Versioned schema with a migration chain: older saves load and migrate deterministically; newer saves are refused with an explicit message and never rewritten.
- B23 Integrity check (checksum/hash): truncation, bit flips, missing keys are detected at load with a specific message; nothing half-applies; other slots are untouched.
- B24 Atomic writes with leftover-temp handling at startup: a newer valid temp is promoted, an invalid one discarded; a `.bak`/`_old` is offered when main is damaged.
- B25 Saves are portable files: export → import reproduces the identical state (same hash); import validates like a load.
- B26 Storage exhaustion (disk/quota full) gives a specific, actionable error; the previous file stays intact; no exception escapes to the page.
- B27 Save/autosave cost is bounded and does not freeze play: no frame > 50 ms (PLAN) / no visible hitch at the safe point.
- B28 Determinism after load: continuation is bit-identical to an unsaved one (Factorio map hash / desync model) — measured over hundreds of ticks, at every kind of moment including mid-combat with in-flight objects.
