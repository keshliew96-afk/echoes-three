## Decisions
- The fix lives entirely in M5b's net files (session / predict / driver): draft.js (PARTY) is untouched — the guest proxy answers partyReplace with the predicted slot exactly as the single-player call does, so the page's existing adopt-the-integer path moves the mark on the press.
- Prediction = input-sequence reconciliation with a host ACK carrying the host tick (no sim / snapshot / protocol-version change: the ack is a bvalue CMD body, unknown kinds are ignored by older code paths). Retire only when the APPLIED replica tick passes the ack tick (clock.tick at the CMD = the last completed tick whose snapshot was already captured) — never on "the echo equals the prediction", which would flicker on S then W inside one RTT.
- Predicted ops are idempotent sets, so the arbitrary interleaving of the reliable CMD channel and the snapshot channel cannot produce a wrong intermediate mark.
- A guest's __echoes.state().run shows its predicted own card (the precedent: a guest's state() already shows its predicted own body); the authoritative replicated card stays readable via net.session.partyShadow().authoritative.
- Every applied party CMD is acked (not only replace / pick), so the shop marks / sockets can be predicted later the same way; only the swap card's replace + pick are predicted now (the finding's scope).
