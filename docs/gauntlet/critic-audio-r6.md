## Step 1 — BLIND benchmark checklist (written before any Echoes capture was viewed)

Reference systems: Wwise/FMOD bus mixing as shipped in Hades (FMOD Studio) and Dead Cells; the dB-perceptual volume standard of shipped PC games; HTML5 games with correct autoplay handling. Each item is a concrete, testable behaviour.

### A. Bus mixing (Hades / Dead Cells, FMOD/Wwise style)
- A1 Bus hierarchy: Master -> Music, SFX (optionally UI / ambience sub-buses). Master scales every child; a child fader never changes a sibling.
- A2 Fader moves are smoothed (parameter ramp ~10-100 ms) — no zipper noise / clicks when dragging a slider.
- A3 Music state changes (menu -> hub -> combat -> boss -> victory/defeat) crossfade or transition on a musical boundary; never a hard cut, never a silence gap > ~1 s.
- A4 Master-bus limiter/compressor: dense combat (boss fight, many hits) never exceeds 0 dBFS true peak / sample peak <= 1.0.
- A5 Voice/instance limiting per event (e.g. hit sounds capped to N simultaneous, oldest stolen) so mass hits don't sum into mush or clipping.
- A6 Variation: per-trigger pitch/volume randomisation (+-1-3 semitones / +-2 dB) so repeated hits don't machine-gun.
- A7 Music ducks (sidechain / snapshot) under key moments (boss telegraph, stingers) or the pause menu applies a snapshot (low-pass / duck).
- A8 Spatial SFX in a top-down game: stereo pan follows the source's screen-x relative to the listener/camera (left source -> left channel louder), distance attenuation for far/off-screen sources.
- A9 Coverage: every gameplay-relevant event has a sound — hit, kill, heal, skill cast, enemy telegraph/wind-up, boss slam/quake, UI navigate/confirm/back.

### B. dB-perceptual volume standard (shipped PC games)
- B1 Slider 0..100 maps to perceived loudness: a log/dB taper (e.g. -60 dB..0 dB, or amplitude x^2..x^3), so 50% sounds roughly "half" (~ -10 to -20 dB), not a linear amplitude 0.5 (-6 dB).
- B2 0% = true silence (gain 0 / -inf dB), not a residual -60 dB hiss.
- B3 100% = unity (0 dB) — no hidden boost, no attenuation.
- B4 Numeric readout next to every slider; keyboard arrows step it (1-5%), PageUp/PageDown or Home/End jump; mouse drag and click-to-set work.
- B5 Master mute toggle independent of the slider value; unmute restores the previous level.
- B6 Changes are audible live (SFX slider plays a preview blip), and persist across a reload/restart.
- B7 "Mute when unfocused / in background" option (browser: visibilitychange/blur) — common on PC.
- B8 Reset-to-defaults available; sane defaults (Master 100 / Music ~60-80 / SFX ~80-100).

### C. HTML5 autoplay handling
- C1 AudioContext is created or resumed on the first user gesture (key, click, touch, gamepad button where allowed); no uncaught "AudioContext was not allowed to start" errors.
- C2 After the unlock gesture, music is audible within ~0.5 s; repeat gestures never double-start music.
- C3 When the policy allows autoplay (e.g. --autoplay-policy=no-user-gesture-required), music begins at the title without a gesture.
- C4 While blocked, the game stays fully playable and honestly indicates sound is waiting for a click/key (no fake "sound on" state).
- C5 Tab hidden -> audio suspends or mutes; tab visible -> it resumes (no stuck-suspended context).

### D. Balance (dialogue-free mix)
- D1 SFX peaks sit above the music bed by a sane margin (~6-15 dB peak-to-music-RMS) at default settings; music never masks combat cues, SFX never make music inaudible.
- D2 Integrated loudness in a sensible game range (roughly -14 to -24 LUFS-ish; RMS around -20 dBFS for the music bed).
