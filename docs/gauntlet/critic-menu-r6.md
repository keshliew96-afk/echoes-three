## 1. BLIND BENCHMARK CHECKLIST (written before looking at any Echoes capture)

Sources: Hades (Supergiant), Celeste, Hollow Knight, Slay the Spire title/options screens, and the shipped-game settings conventions of Unreal (GameUserSettings: resolution scale, window mode, v-sync, frame limit, "keep these settings?" confirm) and Unity (Screen.fullScreenMode, QualitySettings.vSyncCount, Application.targetFrameRate, PlayerPrefs).
Each item is concrete and testable; the Echoes score is in section 4.

### Title screen
- B1 Focus on arrival: the first actionable entry (Continue when a save exists, else New Game) is focused and visibly highlighted the moment the menu appears, before any mouse/keyboard input (Hades, HK, Celeste all show a highlighted cursor at load).
- B2 Continue/Load honesty: Continue/Load only enabled when a save exists (StS shows Continue only mid-run; HK shows empty profiles as "New Game"); an empty Load never leads to a dead screen.
- B3 Resolution-independent layout: at 16:9 from ~1024x576 to 2560x1440 the menu keeps proportion (type scales with height), nothing clipped or overlapping, body text >= ~14 px at the smallest size, logo never overlaps entries.
- B4 One focus model: mouse hover moves the same highlight keyboard/gamepad use (Hades/HK); never two highlighted entries at once.
- B5 Keyboard: Up/Down (and W/S) move, Enter/Space confirm, Esc = back exactly one level; ends wrap or clamp consistently on every list.
- B6 Gamepad: D-pad and left stick move with an initial delay (~300-500 ms) then repeat (~80-150 ms); A confirm, B back; prompts/glyphs switch to pad when the pad is used (Hades, Celeste).
- B7 Focus memory: backing out of a sub-menu returns focus to the entry that opened it (Hades, HK).
- B8 Responsiveness: a menu action produces visible change within 1-2 frames (< ~50 ms); transitions are short (< ~300 ms) and never eat input.
- B9 Destructive confirm: New Game over an existing run asks before discarding it (StS "abandon run?"; HK separate slots).
- B10 Exit: a confirm step; on desktop the app closes. (Browser truthful equivalent required: a browser tab cannot close itself unless script-opened.)
- B11 Living title: animated backdrop + title music that starts on (or after the first) input; no silent dead frame.

### Settings (display)
- S1 Render/resolution scale: a percentage slider/stepper (Unreal r.ScreenPercentage 50-100 % or 25-200 %) that changes the internal buffer size live, with the resulting resolution shown.
- S2 Window mode: Fullscreen / Windowed (Borderless) options; the displayed state always matches the real state, including when the OS/browser changes it (Alt+Enter / Esc / F11).
- S3 Keep-settings confirm: changing window mode/resolution opens "Keep these settings? Reverting in 10-15 s", reverting on timeout or Esc (Unreal, Windows, HK resolution change).
- S4 V-Sync: On = frame cadence locked to display refresh (no tearing); Off = uncapped/limited by frame limit; label/tooltip explains what it does.
- S5 Frame-rate limit: 30 / 60 / 120 (/144) / Unlimited; measured fps matches the cap within a few %.
- S6 Instant preview + apply/revert: changes preview immediately; a Reset-to-defaults entry exists; leaving with unapplied changes asks (Unreal/Unity menus) or everything auto-applies (Hades/Celeste) — never a silent mix.
- S7 Description line for the focused setting (Hades/Celeste show a description of the highlighted option).
- S8 Left/Right change the focused value (carousel) for keyboard and D-pad; value text updates immediately.
- S9 Persistence: settings survive restart; a corrupt/partial config falls back to defaults per key without crashing and is rewritten valid.
- S10 Same settings reachable from the title and from the pause menu, same state.
- S11 Resize handling: the UI relayouts and the 3D view keeps correct aspect (no stretch) on window resize without reload.
- S12 Focus loss: the game pauses/mutes or keeps running per an explicit option (Unity runInBackground; HK pauses on focus loss); returning focus restores input without stuck keys.
