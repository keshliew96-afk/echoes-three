## 4. Findings

### Must-fix
- **DEP5-F1 — a refused connection looks like a dead server, and behind a proxy that is not on loopback every player counts as one IP.** (a) tools/gntcdeploy5-paas.mjs: default `--max-per-ip 16`, a reverse proxy on another address (the shape of a docker-compose Caddy container, a PaaS edge such as Render / Fly / Railway, or a proxy on another host) forwarding 20 players, each with its own X-Forwarded-For → players 1–16 get 101, **players 17–20 get HTTP 429**. There is no option to trust that proxy's X-Forwarded-For (the README table only covers "behind a local proxy"). (b) The refused player is told, 670 ms after pressing Multiplayer, "Can't reach the Echoes server … it isn't running. In the game folder run npm run net". The same false copy appears for an Origin refused by `--origins` (S9: 403 → "run npm run net", 649 ms). (c) The server log printed nothing for either refusal. On a public server (the README's "Put the game on the internet") the 17th player cannot join, is told the site is down, and the host finds /health "ok" and a silent log. This fails benchmark B18 and half of B6 ("a clear fix, never a dead end"). Expected: a documented trust-proxy option (or trusting the X-Forwarded-For of private-network peers), a player-facing "the server refused this connection (full / not allowed from this page) — ask the host" (the client can tell a refusal from a dead server with a same-origin GET /health), and a throttled log line per refusal.

### Advisories (measured, not blocking)
- A1 README "Updating": during `npm run build` under the running server, `/` answers **404 "Not found" for 0.32–0.47 s** (11 and 16 consecutive 30 ms samples; the entry chunk and version.json 404 too). A player who opens the link or presses Reload in that window gets a bare "Not found". Build to a new directory and swap it (Netlify/Vercel style) to close the window.
- A2 Nested extension-less URLs (http://host/join/C7XWE) get the index.html fallback. Its relative `./assets/*` then 404, so the boot card says "A game file didn't arrive … check the connection and reload", and Reload fails the same way. The fallback exists for client routes, which the game does not have; a 404 or a redirect to `/` would be honest.
- A3 After a server crash and restart, a guest who presses F5 is offered "Rejoin L5KP9? Your Tank seat is held for a minute" for a room the new process never had. Rejoin → "room closed" for about 3.7 s → title. It recovers, but the offer is false.
- A4 Server CLI: `--help` starts a session server instead of printing usage, and a mistyped flag (`--statc dist`) is silently ignored, so the server runs WITHOUT the game and gives no warning.
- A5 Sharing, compared with skribbl / gartic: the lobby shows the code in large type and the page link, but there is no one-click copy and no link that carries the code, so the link and the code have to be sent separately.
- A6 PLAN §14.1 details: (a) on an https page with a saved wss:// address, a `?net=ws://` param is skipped and resolution falls to `site`, not to the saved address (harness links only); (b) the saved-custom note reads "Custom address — "Reset to automatic" goes back to this site's server" without the URL (the URL is only in the input).
- A7 A sub-path reverse-proxy deploy (example.com/games/echoes/) looks for the socket at the domain root /echoes. The README does not say so.
- A8 `npm ci` on the server installs dev tools and reports "1 high severity vulnerability" (dev-only).
- A9 Copy left over from before round 5: the lobby share panel says "The host plays the Healer and makes the build choices between rooms; everyone else plays an ally", which contradicts the PARTY rule that each human builds their own character (for the PARTY / net owners). The README intro still says "Three expeditions (…), each a full run", which predates the campaign model.
