## 5. Must-fix failures

### DEP6-F1 (= DEP5-F1, open since round 5; no fix-DEPLOY-r5 exists) — a server that REFUSES a player is reported as "not running", and the server logs nothing
- Evidence (P9 / S13): behind a reverse proxy that is not on loopback (a Docker or PaaS edge), the default per-IP cap counts every player as one IP. Of 20 distinct players, 16 get 101 and players 17–20 get **429** (/health connections 16). Player 17 then opens the page, and 854 ms after the click reads "Can't reach the Echoes server … it isn't running. In the game folder run npm run net …".
- A page from another origin sent to a `--origins self` server gets **403** and reads "Can't reach … That is the custom address saved … run npm run net …". Settings ▸ Check says "Can't reach ws://192.168.1.45:7940/echoes (unreachable) — is the server running there?".
- In both cases the server answered HTTP /health the whole time, and its log gained **0 lines**.
- Why it is must-fix:
  - The binding PLATFORM HONESTY rule requires honest UI labels. These statements are false, so the player and the host are sent to debug a server that is already running.
  - The PLAN §14.1 copy table covers unreachable servers and says nothing about refusals. Following the PLAN therefore does not make this copy correct for a refusal.
  - The client can tell "running but refusing" from "down" in the browser: the site's /health answers over HTTP. The server already sends `Retry-After: 10`, and the client ignores it.
  - The cap has no trust-proxy option for a proxy that is not on loopback. The project's own live host, Render, is a PaaS edge and only works because `--max-per-ip 0` was passed by hand.

### DEP6-F2 — the lobby's SHARE panel tells every joining player the opposite of how builds work
- Evidence: zc-static-host-lobby-full.png, and every lobby in P1/P2/S16, says "The host plays the Healer and makes the build choices between rooms; everyone else plays an ally."
- Measured in S19 (guestbuild.json, gb-guest-reward.png): after room 1 the GUEST (Tank) gets its own draft, "FOR THE TANK · NEW SKILL — SWAP · Shield Wall · choose one to replace, or leave", while the host gets "FOR YOU — THE HEALER".
- This is the binding PER-CHARACTER BUILDS rule working as specified ("in multiplayer each human builds their OWN character"). The lobby copy is false, and it sits on the hosted-multiplayer join surface that DEPLOY owns (PLAN §14 ownership: lobby copy).
- It was noted as an advisory in r5 and in the r6 net critic report, and is still not fixed.

## 6. Advisories
- A1 No invite link (B3): no URL form carries the room code, and the lobby has no copy-link or copy-code control. The skribbl.io, gartic.io and krunker.io convention is one link straight into the room.
- A2 The README "Updating" steps run `npm run build` in place under the running server, so `/`, the entry chunk and version.json answer 404 "Not found" for about 0.35 s (11 consecutive samples, gntcdeploy6-updatewindow.json). Fix by building to a temp dir and swapping, or by documenting the restart order.
- A3 After a server crash and restart, the F5'd guest is offered "Rejoin <code>? Your Tank seat is held for a minute" with Rejoin focused, for a room the new process never had. Rejoin shows "room closed" for about 2.7 s, then the title. Open since r4.
- A4 The server ignores $PORT: with `PORT=7944` it still tries 7800. README "Host it on a server" has no PaaS (Render / Fly / Railway) section, although the project's live deployment is on Render.
- A5 A dead custom or ?net= address (ECONNREFUSED) takes 4.60–4.67 s to show the unreachable panel, against a 5 s gate. A site that answers 404 or 502 shows it in 0.57–0.85 s.
- A6 Minor PLAN §14.1 deviations:
  - The saved-custom note reads "Custom address — “Reset to automatic” goes back to this site's server", with no URL; the URL is only in the input.
  - On https, a skipped ?net=ws:// falls back to `site` instead of the saved wss:// address. Nothing is lost: the saved address returns on reload.
- A7 Sub-path deployments: the automatic address is always the origin root /echoes (S9). The README says nothing about reverse proxies under a sub-path.
- A8 Boot time dominates a guest's wait: on the real GPU, page load to title takes 13.6 s and load to in game 17.7 s, while the network part of the join is under 3 s. The index chunk is 1 558 kB (517 kB gzip) and triggers the bundler's >1300 kB warning.
- A9 The README "How to play" section contradicts the campaign model: "(once you have won Act I, the portal offers an expedition picker)", "Three expeditions …, each a full run", and a pause menu list without Quit to Lobby.
- A10 README step 1, `npm ci`, prints "1 high severity vulnerability" (sharp <0.35.4, libheif advisories).
- A11 Guessing `?room=<code>` as an invite URL boots a harness room state, not the join flow (P4).
