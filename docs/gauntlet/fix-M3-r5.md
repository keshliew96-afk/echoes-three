## Decisions
- D1 Selection ticks live in ONE M3 helper (src/audio/uiselect.js) fed by a cheap per-page signature polled once per frame, not in every key / pad / mouse handler: a poll hears every path that moves the selection (keys, pad, wheel, click, hover, the Replaces pick that also moves the Take focus) with one frame of latency, and the pages keep no audio code. A change counts only if a player input came within 400 ms (combat keys never count: inputs are marked only while a page is open and settled), never on a commit key (its own cue plays), never when a page opens / closes; 70 ms between ticks (a hover that also moves the selection plays once, a gliding held arrow ticks like a scroll ticker).
- D2 The run pages speak the SAME app `nav` event the screen manager emits (screen 'run:<page>' / 'socket:socket'); a character switch is 'tabNext' (ui_tab), everything else 'down' (ui_move) — the engine keeps one nav->cue map (PLAN §3.5 last row). App-menu pointer hover (screen manager 'focus', source mouse) ticks ui_move source 'hover' so menus and pages follow one rule (the benchmark's hover ticks).
- D3 Hover = real pointer motion only, detected by a changed clientX/Y (movementX is 0 on a pointer's first event, so a single harness move or a first real move would be missed; a re-render under a still cursor re-sends the same position), keyed by the item's index on the page (a rebuilt card is not a new hover); sold cards never tick.
- D4 UI staging at the ceiling + a small sidechain duck instead of raising the UI bus default or cutting the music: the music tap RMS is -23..-25 dBFS at defaults and the master median (-22.5) rests on it (band floor -24), so the music cannot drop; the UI default slider (0.7) and the -12 dBFS ceiling are PLAN values. -12 alone gives ~+4 dB median but only ~+2.6 at the loudest windows; the -3 dB duck (held for the cue's transient + 0.15 s, tau 0.12 s) adds ~2-3 dB inside the window and is the Wwise / FMOD interface-duck pattern. Exempt: the Audio tab's channel previews / Test phrases (they judge a channel's own loudness — a dragged Music slider must not modulate the music it sets), measureCue, and any cue while the pause duck already holds the score.
- D5 Baked UI samples are played from their own measured peak (render worker), not CUE_CAL: a 20 ms tick with a noise layer lands +-2 dB off its live-synth design peak per render. Limited to the UI bus (the one bus a gate measures by peak); SFX keep CUE_CAL so G3.3 / the SFX margin stay as certified.
- D6 PLAN §16.4 gaps found while fixing (same selection surface): the shop gets keyboard card focus (A/D, arrows = the pad's focus; Enter buys the focused card, Enter on the lamp advances; the shelf opens on the lamp; the right hint says what Enter does, two lines in one grid cell so nothing re-flows) and the door picker a pad map (d-pad focus, A walks through). Not changed (reported): the victory/defeat card and the level-clear card have no pad map either (they auto-advance / auto-return on their own).
- D7 The first wave's wave_start no longer plays 3 dB under the others (at the UI staging level it sat under the combat music); room_start + wave_start at the same moment sum on the UI bus (below the limiter at defaults).
