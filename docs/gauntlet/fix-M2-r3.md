## Decisions (where PLAN is silent)
- D1 (F1) Hover INTENT, not click-to-select: PLAN §3.3 requires "hover focuses" and "click = confirm on that item", and the benchmark (Skyrim-style list + preview) previews on hover; so the ring follows the pointer at once, the detail panel follows only a row the pointer rests on (180 ms, 450 ms when the last motion was aimed into the panel — Amazon/macOS "menu aim"), keyboard / gamepad select at once, a row click acts on that row. Leaving the list from a merely-crossed row returns the ring to the selected row so ring and panel never disagree. Rejected: click-to-select (breaks "click = confirm" and hides the preview), a plain dwell without aim (a 120 ms rest was inside measured pointer-event jitter: 60-146 ms gaps on steady synthetic paths).
- D2 (F2) Card kind lives in meta (meta.campaign.card), not only in state, because the catalogue / title read meta only; wording in one pure module (src/save/describe.js) shared by the saves screen and the title so they cannot drift. Setting-out wording "Setting out — Level II · The Sunken Mill" (no room: the level has not begun); a clear card names the next level. Files written before v0.5.106 fall back on meta.room (0 = setting out, 8 = clear card) — no migration or schema bump needed (meta is outside the hashed state).
- D3 (F3) A save must never wait seconds on its picture: the picture is requested first and encoded while the file is built/verified, the write waits at most 250 ms, a later picture is attached to THAT save only (savedAt + hash match; overwrite/delete drop it), a stale picture of a previous save is removed rather than shown. The encoder is an inline Blob worker (the codebase's pattern: net metronome, audio render worker) — no network fetch, so neither a busy dev server (measured 1.4-8.3 s) nor a slow host can delay it; prewarmed ~1.2 s after boot. A worker slower than 900 ms is bypassed by a main-thread encode of a spare snapshot (29-39 ms main thread, only on that rare path) so G2.3's picture always lands.
- D4 (F3 input) "Saving…" on the row + button the frame after the press (an honest pending state); a press made while a save / confirm runs is REPLAYED when it ends, re-resolved against the slots as they are then (never a stale "empty slot" closure), so a 2nd Enter on a just-saved slot opens the overwrite confirm exactly as on a fast save.
- D5 Detail list rows size to wrapped content (grid-auto-rows max-content) — an overflow:hidden grid item has a zero automatic minimum, so the second line of Where / Party / Skills was clipped in a short panel; the list scrolls instead.
