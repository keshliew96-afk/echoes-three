## Decisions
- D1 The pointer is a nav source like keys and pad: the root cause is that nav.js never announced a pointer activation, so the fix announces it there (the engine still only listens to app `nav` events — §3.5 "never the other way round"), in the CAPTURE phase so it precedes the control's own handler exactly as screens.nav's emit precedes el.click(). The engine's existing 45 ms fold (a nav cue swallows the setting tick it causes) then makes a click on Curve / Mute / a select chip one ui_confirm, as Enter already was — one activation, one cue, whatever the device.
- D2 The activation cue is a property of the ITEM, applied to every device (Hades / Dead Cells: a Back button sounds like back whether clicked, pressed with A or with Enter): disabled / locked -> ui_deny, tab chip -> ui_tab, Back / Cancel -> ui_back, else ui_confirm. So Enter / A on Back, Keep Playing (ap-confirm-cancel) and a tab chip now play ui_back / ui_back / ui_tab (were ui_confirm) — the keyboard and pad changed to match the role, not the mouse to match a role-blind Enter. Roles are read from structure (disabled attributes, ARIA role, the existing `-back` / `-cancel` id convention every Back / Cancel button already follows), never from label text, because the queued I18N build translates labels.
- D3 What counts as an activation: a trusted click with detail > 0 whose press began on the SAME [data-nav] item of the top screen. Keyboard-made clicks (detail 0) and the nav confirm's synthetic el.click() (untrusted) are left to the nav that made them (no double); a press slid off the item is no activation (the browser fires no click on it either); a tap that dismissed the splash lands its click on a title item (measured: target ap-title-new) — the title's 350 ms open guard ignores it, and the press-on-the-same-item rule keeps it silent too. Sliders, text fields and selects are adjusted / typed into, so their own tick (or none) stays.
- D4 Natively [disabled] buttons (title Load Game with no saves, pause Save Game when saving is refused, lobby Start) receive no click event in Chrome but do receive pointerdown / pointerup (measured, tools/gntfixM36-disabledev.mjs), so their release announces the denied activation; aria-disabled-only items (the locked Level Select cards) get a click and deny through the same path. Keyboard / pad focus never lands on a disabled item (movement skips it), so ui_deny for keys only appears when the focused button disabled itself under the press (the press then really does nothing — honest).
- D5 No new mixer behaviour: the click cue is the existing ui_confirm / ui_back / ui_tab / ui_deny sample at the -12 dBFS UI ceiling with the existing UI duck (critic's -20.37 dBFS on the UI tap at defaults); the hover tick that may precede it is unchanged (the 70 ms hover/nav guard keeps a click's own focus move from adding a tick).
- D6 Advisories V1-V8 of critic-audio-r6 are not must-fix and were left as they are (V5's level-select no-move ticks and V6's title-root Esc tick live in the screen manager's emit-before-act order — M1's file; noted for the next audio round).
