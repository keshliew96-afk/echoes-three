## Failures

1. **Boss-room banner shows a dead boss for the whole add mop-up** —
   `captures/yhd-boss-hp.png` and `captures/yhd-tint-boss.png`, Zone-2 box
   (419,14,761x35): "THE HOLLOW STAG" + empty violet bar + **"0/200"** while
   the room is live with 7 adds and the party fighting. `yhd-boss-spawn`
   per-100 ms timeline after `skipToRoom 8`: `boss_spawn t367 hp=200` →
   banner "200/200" → 172 (+331 ms) → 146, phase 1 adds (+552 ms) → 100,
   phase 2 (+671) → 44, phase 3 (+811) → 19 → 7 → **`death t431 stag`
   (+1.07 s)** → `run.boss = {active:true, cleared:false, hp:0, phasesFired:3,
   adds:7}` and banner **"0/200"** from +1163 ms onward (still so at +1.7 s;
   `yhd-boss-hp` reads it at ticks 401, 476, 501; `bossHp`/`killBoss` return
   null because there is no entity). Round D measured this banner at 100/200
   mid-fight on v0.4.13. Root cause: commit 04b015c removed the Stag's
   "Hollow Seal" HP floor in `src/sim/boss.js` ("NO immunity, no HP floor"),
   whose own comment says the party's ~150 dps kills a plain 200 HP Stag in
   about one second. Fix direction — sim (`src/sim/boss.js`): the Stag must
   outlive its three §11 add phases (restore the per-phase floor/seal, or size
   its HP to the intended fight length); and when the Stag is dead with adds
   still up, `view()` must not report `active && !cleared && hp 0` — either
   mark the boss cleared and hand the room to a kill_all-style "N LEFT" cue,
   or expose the adds count. HUD hardening (`src/ui/hud/banner.js` boss
   branch): treat `boss.hp <= 0` as "no boss" and fall through to the room's
   alive-enemies cue (or hide) instead of printing "0/200"; `runBoss` in
   `index.js` should require `b.hp > 0`. Re-verify with `yhd-boss-spawn.json`:
   the banner must never read 0/200 while `room_cleared` has not fired.

2. **`?scene=arena&room=kill_all` boot: live wave room with no banner and no
   pointers** — `captures/yhd-smoke-arena.png` + console: `room {mode:
   kill_all, cleared:false, alive:1}`, enemies attacking, yet `hud.combat() =
   {combat:false, runActive:false}`, banner `none`/`gated`, `tmNodes 0`,
   banner box ink 0. `readCombat()` in `src/ui/hud/index.js` returns false
   whenever `runSystem.isActive()` is false, so the harness boot that
   docs/TESTING.md and the task brief use for "a wave room" draws no combat
   chrome (the whole criterion-6 legibility fix is absent there). No player
   path reaches this state, so severity is low, but it will mislead every
   future critic using the sanctioned URL. Fix direction: mirror the sim's
   own predicate — `run.js` already exposes `combatAllowed()` =
   `!everStarted || (active && phase === 'combat')` — e.g.
   `combat = rs.combatActive() || (rs.combatAllowed() && room && !room.cleared)`.
   `everStarted` stays true after any run, so the reward/end-card/camp gate
   (F2) cannot reopen. Re-verify with `yhd-smoke-arena.json` (banner
   `kill_all`, pointers drawn) and `yhd-camp-leak2.json` (still gated).

## Advisories (not blocking)

- **A1 Fade-out under load.** The DOM flip is synchronous at `run_end`, but the
  150 ms opacity transition is swallowed by a ~250 ms main-thread stall while
  the end card builds: 321 ms on a 27 fps loaded box, 211–245 ms when quiet.
  Defer the end-card DOM construction by one rAF after `run_end` (or build it
  off-screen at `room_start` of room 8 / on the defeat edge) so the fade
  always paints inside 300 ms.
- **A2 Stale text inside the hidden banner.** On reward/path/shop
  `banner.debug.state().text` still reads "WAVE 1/3 3 LEFT" and the box is
  516 px wide (the bar element becomes `display:block` in mode `none`) —
  invisible at opacity 0, but `hide()` only runs on the run-end events. Clear
  the label/pips and collapse the bar whenever `update()` lands on `none`, so
  a future style slip cannot resurrect a stale wave counter.
- **A3 Harness note.** `spawn` returns null outside live combat (the new spawn
  gate), so the pointer gate could not be fed a real enemy on the end cards —
  `yhd-gate-victory-leak` / `yhd-gate-defeat-leak` prove only that no enemy
  exists there. The gate was exercised instead by the stray `startRoom` in
  camp (live uncleared room, 5 pending; HUD stayed dark).
- **A4 Downed busts.** Identity now rides entirely on the chip text and the
  rims (whole-tile diff 16.2 vs 25.1 healthy); the rotated grey busts are
  still interchangeable. A small class glyph in the crop band would lift the
  whole-tile number without touching the ring.
- **A5 "0.0" numeral.** `(remainingTicks/60).toFixed(1)` prints "0.0" for the
  last 1–2 ticks (`yhd-size-1024-bar2x.png`, slot 1). Floor the display at
  "0.1" or hide the numeral once remaining < 3 ticks.
